# Независимый реестр и закрытое восстановление

Код проверяется на одноразовых БД. Размещение реестра, бекапы, сроки копий и
реальное восстановление настраиваются только на VPS по [плану](refactoring-plan-2026-10-26.md#vps-stage).
Правила и сроки не дублируются здесь: [политика аккаунта](account-lifecycle.md).

## Реестр

`ACCOUNT_DELETION_REGISTRY_DRIVER=database` выбирает PostgreSQL-адаптер;
по умолчанию `unavailable`, удаление выключено. Соединение `deletion_registry`
задаётся `DELETION_REGISTRY_HOST/PORT/DATABASE/USERNAME/PASSWORD/SSLMODE`.
SSL mode по умолчанию `require`. БД реестра должна иметь другое имя и не входить
в восстановление основной БД. Раздельные роли/резервирование/доступы проверяются на VPS.

`ACCOUNT_DELETION_REGISTRY_NAMESPACE` — постоянный идентификатор установки,
8–100 латинских букв, цифр, `_`/`-`. Сохранить его вместе с конфигурацией:
смена namespace скрывает прежние удаления. На явно подготовленной отдельной БД:

```bash
php artisan accounts:registry-init --database=family_education_registry
```

Команда не создаёт БД/пользователя; проверяет точное имя. Таблица `deletion_records`
не относится к миграциям приложения. Ключ namespace/user_id, значения T0, версия
политики и результат; без email, исходного payload и request token. Запись
фиксируется отдельной транзакцией с `synchronous_commit=on`, повтор совпадающей
записи безопасен, противоречие не перезаписывается. После инициализации runtime-роли
достаточно SELECT/INSERT; DELETE для очистки по политике — отдельная операция.

## Очистка очереди

`AccountQueueCleaner` читает сериализованный payload без создания объектов или
выполнения job. Database jobs/failed_jobs очищаются в транзакции удаления.
Redis ready/delayed/reserved очищаются после commit по UUID задания во всех
состояниях; rollback основной транзакции не удаляет задания из Redis.
`accounts:purge-expired` ежечасно повторяет очистку, включая запоздалый release job.
При ошибке запись удаления сохраняется для повтора; лог не содержит payload.

В `ACCOUNT_DELETION_REDIS_QUEUES` перечислить все очереди через запятую;
очередь из `REDIS_QUEUE` также включается. Используются штатные phpredis и
database failed_jobs. Другие соединения/хранилища требуют отдельной проверки.

## После восстановления

Только на выбранной закрытой цели, с остановленными HTTP, queue, scheduler и
poller. Реестр должен оставаться актуальным, а не быть восстановленным из старого
dump приложения. Выключить `ACCOUNT_DELETION_ENABLED`, `TELEGRAM_ENABLED`,
`MAX_ENABLED`; сохранить исходный APP_KEY и namespace. Затем из контейнера
именно этой цели:

```bash
php artisan down
php artisan accounts:reconcile-restored --database=family_education --workers-stopped
```

`--workers-stopped` — подтверждение фактической остановки оператором, не команда
остановки процессов. Maintenance mode сам не останавливает уже работающие jobs.

Сверка сначала передаёт восстановленный outbox в независимый реестр, проверяет
все его записи, применяет удаления с первоначальным T0 и очищает просроченное.
Очищаются старые session/reset/database jobs/failed_jobs и все перечисленные
Redis-очереди; отзываются remember tokens, сессии и все Telegram/MAX-привязки.
Sequence users поднимается выше известных удалённых ID, отсутствующих в snapshot.
Неподдерживаемая версия/конфликт/сбой не считается успехом. Команда повторяема,
но не открывает приложение: при любом результате maintenance остаётся включён.

Перед открытием на VPS проверить доступ, сроки, очередь, повтор сверки и
контрольные записи. Для release tooling восстановление требует отдельного
согласованного перехода состояния; не редактировать state.json ради допуска `open`.
