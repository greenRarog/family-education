# Правила модерации

Утверждённая действующая спецификация; C01–C14 реализованы.
[Итог приёмки](refactoring-plan-2026-10-26.md#stage-c),
[API и проверки](../README.md#модерация), [правила B](action-rules.md).
Контакт `MODERATION_APPEAL_EMAIL` временно `family-education@help.ru`;
работоспособность и ответственного подтвердить перед выпуском.

## 1. Утверждённый объём MVP

Одна административная роль; жалобы на объявление или пользователя; ручная
блокировка аккаунта без срока; отдельное обратимое скрытие объявления.
Жалоба сама по себе ничего не скрывает и никого не блокирует. Удаления данных,
автоблокировки по числу жалоб, предупреждения/страйки, временные санкции,
пользовательский чёрный список и самостоятельная модерация сообщений не входят.
Сроки хранения/анонимизацию не определяем вместо D01/D02.

Профиль педагога уходит из публичного доступа при блокировке его владельца.
Самостоятельного скрытия уже одобренного профиля нет. Для MVP
принята эта грубая мера; если позднее понадобится мягкая санкция только для
профиля, до реализации следует добавить отдельные задачи API/UI/приёмки.

## 2. Связь с остальными правилами

Роли, владение, статусы и email-проверки B сохраняются. Модерация добавляет
ограничения; политика удаления/хранения и общая унификация истечения остаются в D.

## 3. Роли и полномочия

| Роль/состояние | Права по C01 |
| --- | --- |
| Гость | Публичное чтение; жалоб и административных действий нет. |
| Активная семья/педагог с подтверждённым email | Жалоба в доступном контексте; прежние права B с дополнительными ограничениями C. |
| Семья/педагог без подтверждённого email | Прежние права B, подача жалобы после подтверждения; контакт для апелляций/обращений доступен без него. |
| Заблокированный пользователь | Ограниченный кабинет и история по §5; обычные жалобы недоступны, апелляция доступна. |
| Администратор | Очередь жалоб, минимальные карточки пользователей, объявления и журнал; блокировка/разблокировка, скрытие/восстановление и решение жалобы с причиной. Чтение без verification, изменения с verification по B. |

Новых ролей модератора/суперадминистратора нет. Через MVP API нельзя блокировать
себя или другого admin, менять роли, удалять аккаунты либо читать чужую
переписку. Компрометация admin требует отдельной операции владельца сервиса;
новый аварийный доступ здесь не проектируется. Admin может принять меру без
жалобы, но обязан указать причину. Обычная форма жалоб для admin не нужна.

## 4. Жалобы

**Два типа объекта:**

- `advertisement`: чужое объявление, которое заявитель вправе читать в момент
  запроса: публичное либо прежнее закрытое в своём диалоге. Уже скрытое
  объявление повторно выбирать нельзя; на собеседника можно пожаловаться из
  сохранённого диалога. Саможалобы запрещены.
- `user`: другой пользователь из видимого публичного профиля педагога или
  своего существующего диалога (включая rejected и заблокированного собеседника).
  Сервер проверяет контекст и определяет адресата; произвольного перебора ID
  пользователей нет. Жалоба на семью без диалога подаётся на её объявление;
  публичный ID владельца ради этого не раскрывается.

Профиль, отклик, отдельное сообщение и диалог не становятся самостоятельными
типами жалобы. Нарушение в профиле/общении описывается в жалобе на пользователя.
Заявитель может добровольно привести короткую цитату в пояснении; форма должна
сообщать, что пояснение увидит администратор. Переписка автоматически не
прикладывается. Это сохраняет приватность, но ограничивает проверку спорных цитат.

| Причина | Объекты |
| --- | --- |
| `spam` — спам, навязчивая реклама | Оба |
| `fraud` — обман, выдача себя за другое лицо | Оба |
| `abuse` — оскорбления, угрозы, преследование | Оба |
| `unsafe_content` — опасные/неприемлемые материалы | Оба |
| `personal_data` — раскрытие чужих персональных данных | Оба |
| `off_topic` — содержание не соответствует назначению объявления | Объявление |
| `other` — другое | Оба, пояснение обязательно |

Согласованные ограничения: пояснение до 2000 символов, для `other` минимум
10 непустых символов; вложений нет. Независимый лимит **3 попытки за 60 секунд
и 10 за 86400 секунд на ID заявителя**, общий между сессиями/объектами.
Это стартовые числа MVP, не результат измерений. Семантика окон/429 соответствует B:
учитываются попытки после auth/CSRF/limiter, 429 не продлевает окно, возвращает
`Retry-After`/`retry_after`; последующие 403/404/422 расходуют бюджет.

Не более одной **открытой** жалобы заявителя на тот же объект независимо от
причины; повтор — 422 `report_already_open`, включая гонку запросов. После
закрытия допустима новая жалоба в рамках лимита; старую нельзя переписывать.
Успех — 201, ID и статус `open`; гость — 401, роль/блокировка/email — 403,
недоступный/несуществующий объект — 404, свой объект/неверные поля — 422.
Форма сохраняет ввод при сетевой ошибке; повтор после потерянного ответа
показывает «Жалоба уже принята». Отдельного кабинета жалоб в MVP нет.

Сохраняются заявитель, тип/ID объекта, контекст, причина, пояснение и время.
Для объявления/публичного профиля — снимок только публичных полей на момент
жалобы; для контекста диалога — ID связи/участников и отображаемые имена,
без сообщений, детей и приватных полей. Снимок помогает разбирать жалобу после
редактирования; это не общая система версий. Исчезновение объекта не удаляет
жалобу/журнал; политика удаления и хранения будет определена в D.

Очередь: `open → resolved` (мера принята или уже действует) либо `open → dismissed`
(не подтверждено/не относится к модерации). Решение требует пояснения;
`resolved` ссылается на применённое действие/действия. Жалобу не закрывать
автоматически после отдельной блокировки/скрытия. Нет in-progress, назначения
исполнителя, массовых решений и автоматического пересмотра закрытой жалобы.
Устаревшая попытка изменить закрытую жалобу — 409, без перезаписи решения.

Текст, личность заявителя, снимок и внутреннее решение доступны только admin.
Владелец объекта получает самостоятельную понятную причину санкции, без данных
заявителя и его цитат. Заявителю — подтверждение приёма; уведомления о результате
и публичная статистика жалоб не входят в MVP.

## 5. Блокировка пользователя и действующие сессии

Блокировка бессрочна до ручной отмены, не удаляет аккаунт и не меняет роль,
email-статус, пароли или статусы откликов. Требуются код причины из §4
(кроме `off_topic`) и пояснение 10–1000 символов, видимое владельцу аккаунта.
Разблокировка также требует пояснения. Количество жалоб не является доказательством.

**Вход остаётся возможным в ограниченный кабинет.** Сессии не удаляются;
сохранённая cookie/remember-me и новый вход дают одинаковые ограничения.
API проверяет актуальную блокировку на каждом запросе; `/api/user` сообщает
состояние, дату и причину самому пользователю. На запрещённое действие — 403
`user_blocked`; reset/verification не снимают блокировку. UI показывает причину
и путь апелляции, обновляет права при polling/возврате во вкладку и сохраняет ввод.

| Действие заблокированного | Решение |
| --- | --- |
| Читать публичные страницы, свои профиль/объявления/историю, непрочитанные | Разрешено в прежних границах доступа; видимость скрытого — §6 |
| Вход/выход, CSRF, подтверждение email/повтор письма, восстановление пароля | Разрешено с прежними проверками и лимитами B |
| Язык, настройки уведомлений, read receipts | Разрешено; отметка прочтения видна собеседнику как раньше |
| Менять профиль семьи/детей или педагога, создавать/редактировать/публиковать/закрывать объявления | Запрещено; данные заморожены на период блокировки |
| Новый отклик, принятие/отклонение отклика, отправка сообщений, обычная жалоба | Запрещено |
| Апелляция через контакт поддержки | Разрешено, в том числе после выхода и без verification |

Объявления заблокированного исчезают из публичной ленты, прямого публичного
просмотра и списка услуг педагога. Публичный профиль и вложенный `public_teacher`
также скрыты; приватный профиль/дети сохранены. Блокировка не проставляет
административное скрытие каждому объявлению и не сбрасывает approved/pending.
Одобрять pending-профиль заблокированного нельзя; отклонить можно по прежнему
сценарию, это не снимает блокировку.

Старые отклики/диалоги/сообщения и их статусы сохраняются. Если **хотя бы один
участник заблокирован**, отправка сообщений и принятие отклика запрещены обоим;
активному владельцу объявления разрешено завершить отклик (`reject`). История
читается обоими, без новых персональных данных. Активный собеседник видит
нейтральное «Общение приостановлено», без причины санкции. Другие диалоги
этого активного пользователя продолжают работать. API проверяет и автора,
и адресата/владельца объявления, а не только текущего пользователя.

Права на новые записи и санкции должны проверяться согласованно при гонке:
после зафиксированной блокировки нельзя записать новое запрещённое действие
на основании устаревшей проверки. Уже завершённые записи не удаляются.
Auth/CSRF/limiter остаются первыми; 429 может предшествовать отказу модерации,
проверка блокировки автора предшествует verification/бизнес-переходу.
Доступ к чужому объекту не раскрывается через подробности чужой блокировки.

Обычные уведомления заблокированному не отправлять; отложенные уведомления
о сообщении/отклике не отправлять также при блокировке второго участника.
Проверять при постановке и перед доставкой mail/Telegram; пропущенные не
досылать после разблокировки. Verification/reset остаются служебными письмами.
Уже отправленное письмо или ранее загруженную страницу отозвать невозможно.

## 6. Скрытие объявлений и видимость

Admin может скрыть любое существующее объявление, включая draft/closed,
с причиной из §4 и пояснением 10–1000 символов. Скрытие — отдельная отметка,
не подмена `draft/published/closed`, не удаление и не блокировка владельца.
Восстановление требует нового пояснения и проверки текущего содержания.
Вне списка скрытое не должно утекать через прямой URL, услуги педагога,
вложенные JSON-ресурсы или описание объявления в списке диалогов.

| Объект/канал | Владелец | Прежний участник диалога | Гость / посторонний | Admin |
| --- | --- | --- | --- | --- |
| Скрытое объявление или объявление заблокированного | Полный свой контент в кабинете, отметка и причина | В контексте диалога только ID/тип и «Объявление недоступно», без описания/карточки | Нет в выдаче, прямой show — 404 | Контент объявления и причина через admin API; без детей и приватных данных семьи |
| Публичный профиль заблокированного педагога | Собственный профиль в кабинете | Публичный URL — 404; прежнее имя в диалоге остаётся | 404, `public_teacher=null` | Публичные поля и статус; это не доступ ко всем приватным полям |
| Профиль семьи / дети | Прежний собственный доступ | Доступа нет | Доступа нет | Новых прав C не добавляет |
| Отклик / сообщения | Только если участник | Прежняя история и статус | Доступа нет | Только если участник; жалоба не открывает переписку |
| Жалоба / журнал | Нет доступа к чужой жалобе/журналу, только своя причина санкции | Нет | Нет | Очередь и журнал доступны в пределах роли |

Публичный show скрытого объявления для любого невладельца — 404, даже при
старом диалоге; заглушка доступна через сам диалог. Владелец может видеть свой
контент также при блокировке, но наличие чтения не даёт права записи.

Если заблокированных участников нет, **скрытие только объявления не останавливает
существующие диалоги**: accept/reject/сообщения работают по B. Новые отклики
запрещены. Это сохраняет уже начатые контакты; для прекращения общения нужна
блокировка нарушителя. Сам текст старых сообщений, включая ранее скопированное
описание объявления, не редактируется и не скрывается автоматически.

Активный владелец может исправить скрытый draft/published или закрыть его по
прежним правилам B; эти действия не снимают скрытие. Closed редактировать нельзя.
Публиковать скрытый draft нельзя. Исправления не меняют снимок ранее поданной
жалобы; admin восстанавливает актуальную версию, не автоматически старую.
Другие объявления и публичный профиль активного владельца не затрагиваются.
При скрытии отменять ещё не доставленные уведомления о новом отклике на это
объявление; уведомления разрешённой старой переписки сохраняются по §5.

## 7. Отмена санкций и апелляция

Разблокировка снимает только блокировку; отдельные скрытия остаются.
Ранее публичные объявления/approved-профиль снова видны при выполнении всех
условий публичности. Черновики не публикуются, private/pending/rejected не
становятся approved. Существующие диалоги снова работают по B, если второй
участник активен и отклик не rejected; отклонённое не открывается заново.

Восстановление объявления снимает только скрытие. Draft остаётся draft,
closed — closed; published возвращается в публичность только при активном
владельце и неистёкшем годе от исходного `published_at`. Ни восстановление,
ни разблокировка не сдвигают срок и позицию публикации. Если срок прошёл,
объявление не становится публичным даже до scheduler: при снятии ограничения
просроченный published переводится в closed (пустой `closed_at` заполняется
моментом этого закрытия), переход отражается в журнале. Общие исправления
истечения, повторных уведомлений и scheduler остаются D08.

Повтор block/unblock/hide/restore уже достигнутого состояния — успешный ответ
с текущим состоянием без новой записи журнала и без перезаписи причины.
Новая санкция после отмены — новый переход/причина/запись. Противоположные
конкурентные действия сериализуются; ответ соответствует выполненному переходу.

**Апелляцию разрешить через один контакт поддержки**, без отдельной системы
тикетов в C. В ограниченном кабинете/у скрытого объявления показать ID решения,
дату, понятную причину и контакт; контакт также доступен без входа. Пользователь
сообщает ID решения, email аккаунта и пояснение; не запрашивать пароль.
Адрес берётся из `moderation.appeal_email`, временно `family-education@help.ru`.
До выпуска нужно подтвердить рабочий адрес и ответственного; наличие заглушки
не подтверждает готовность канала апелляции.

Пересмотр ручной, приостановки санкции на время обращения и обещания срока ответа
нет. Можно пересмотреть ошибочное решение, восстановить исправленный контент
или оставить меру в силе. При отмене — штатное unblock/restore с причиной
«пересмотр» и ссылкой на исходное решение; при отказе — отдельная запись
`appeal_rejected` с кратким обоснованием через admin API/карточку, без изменения
старой записи и без сохранения всей почтовой переписки. Ответ на обращение —
через тот же контакт; отправка почты из приложения не входит в C.

## 8. Журнал

Для каждого перехода: исполнитель, тип/ID объекта, действие, прежнее/новое
состояние, код/пояснение причины, время, связь с жалобой/исходным решением при
наличии. Изменение и запись журнала — одна транзакция: при ошибке откатываются
оба. При решении жалобы вместе с санкцией атомарны все переходы и их записи.
Если мера принята ранее, решение жалобы ссылается на неё. Повтор не создаёт
нового действия. Записи неизменяемы через API даже для admin; исправление —
новое действие. Обычный пользователь не читает полный журнал.

Объём журнала MVP: новые действия C, включая результат апелляции; старые
справочники/словарь и прежняя премодерация pending-профилей не получают задним
числом вымышленной истории. Для просмотра достаточно раздела истории в
карточках пользователя/объявления/жалобы с пагинацией; отдельного общего
экрана журнала не требуется. Личные сообщения и секреты в журнал не включать.
