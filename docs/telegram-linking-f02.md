# Правила подтверждённой привязки Telegram

Сценарий согласован 3 ноября 2026 и реализован. Здесь — пользовательские правила;
[API, конфигурация и эксплуатация](telegram-operations-f03-f05.md) — отдельно.
[Статус проверок и дальнейшие задачи](refactoring-plan-2026-10-26.md).

## Пользовательский сценарий

1. Семья или педагог выбирает «Подключить Telegram» в своём профиле.
   Сайт создаёт попытку и ссылку на бота; обычные уведомления ещё выключены.
2. Пользователь открывает бота и нажимает Start, получает одноразовый 8-значный код
   и вводит его в исходной сессии сайта. Пересланной ссылки недостаточно для привязки.
3. Сайт подтверждает подключение. Получение уведомлений включается отдельным
   переключателем; email не меняется. Нужно объяснить, что уведомление о сообщении
   может содержать его текст.
4. «Отключить Telegram» с подтверждением на сайте удаляет привязку, выключает
   доставку и отменяет попытки. Для смены Telegram сначала отключить прежний.

Один Telegram связывается с одним аккаунтом сайта. Чужая привязка не переносится
автоматически, ответ не раскрывает другой аккаунт. После отвязки доступна новая
привязка. При выходе/смене сессии незавершённую попытку начать заново.
Это канал уведомлений, не вход на сайт или доступ к переписке через бота.

Сценарий доступен семье/педагогу без email verification, также при блокировке;
обычная доставка заблокированным запрещена. Удалённый аккаунт не подключается.
Admin UI подключения не входит в реализованный объём.

## Сроки и ограничения

| Правило | Значение |
| --- | --- |
| Попытка от создания ссылки до подтверждения | 10 минут UTC; на границе недействительна |
| Новая попытка | Отменяет предыдущую, не продлевая её срок |
| Неверный код | 5 ошибок отменяют попытку |
| Создание | 5 за минуту и 20 за сутки на аккаунт; суточное окно от первого запроса |
| Проверка кода и отвязка | По 5 за минуту на аккаунт между сессиями |
| Повтор отвязки | Идемпотентный успех |
| Обычный Start без корректной ссылки | Инструкция открыть профиль, без кода; не более 1 ответа/мин на чат и 30/мин на бота |

Auth/CSRF/проверка текущей личности предшествуют limiter; 429 содержит Retry-After.
Автоматического повтора изменяющего запроса нет. UI — RU/EN/ES, включая ошибки.

## Гарантии доступа и доставки

- Браузер не передаёт произвольный chat ID; кандидат принимается только из
  допустимого private update. Код проверяется для своей попытки/аккаунта/сессии.
- Nonce и код одноразовые; секреты хранятся в виде хешей. Повтор update не меняет
  кандидата/код. Группы, произвольные сообщения, фото и контакты не импортируются.
- Подтверждение атомарно; повтор своей успешной попытки не создаёт новую привязку
  и не включает уведомления. Старый ID без подтверждения требует подключения заново.
- Очередь фиксирует версию привязки; unlink/relink, смена bot ID, блокировка или
  удаление не должны оживлять прежние задания. Unlink и передача провайдеру
  сериализованы. Уже переданное Telegram не отзывается; exactly-once не обещается.
- Отвязка доступна даже при отказе Telegram. Блокировка бота не удаляет аккаунт сайта.
- Код/nonce/token/update не попадают в публичные логи, URL сайта, localStorage
  или обычную очередь уведомлений. Ссылка хранится только в памяти интерфейса.
- После restore все привязки отзываются до доставки: независимого реестра unlink
  нет. Это не заменяет реестр удаления аккаунтов. Очистка попыток, dedup и сроки —
  в [политике аккаунта](account-lifecycle.md#telegram-привязки).

[MAX](max-linking.md) использует согласованный аналогичный пользовательский сценарий,
но собственные Bot API, webhook и независимую привязку.
