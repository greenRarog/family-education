# Family Education — UI Design System

При разработке интерфейса придерживайся единой дизайн-системы проекта. Все новые страницы и компоненты должны визуально восприниматься как части одного продукта.

## Общий визуальный стиль

Стиль: современный минималистичный интерфейс в духе ChatGPT.

Основные характеристики:

* лаконичный;
* спокойный;
* преимущественно текстовый;
* много свободного пространства;
* нейтральная цветовая палитра;
* отсутствие декоративной пестроты;
* минимум визуального шума;
* интерфейс должен выглядеть функциональным, а не рекламным;
* приоритет — читаемость, понятная иерархия и удобство взаимодействия.

Не копируй интерфейс ChatGPT буквально. Используй его как референс по общему визуальному языку.

## Цветовая палитра

Основной фон приложения:

`#f7f7f8`

Поверхность карточек и форм:

`#ffffff`

Основной текст:

`#171717` / `#18181b`

Вторичный текст:

`#6b7280`

Границы:

`#e5e7eb`

Очень светлые разделители:

`#f3f4f6`

Основной акцент:

нейтральный тёмный (`#171717` / `#1f1f1f`), а не ярко-синий.

Синий, зелёный и другие насыщенные цвета использовать только там, где они имеют семантический смысл.

Например:

* ошибка → красный;
* успешное действие → зелёный;
* предупреждение → жёлтый;
* информационное сообщение → нейтральный/сдержанный цвет.

Не использовать яркие цвета просто ради украшения.

## Типографика

Типографика должна быть простой и хорошо читаемой.

Предпочтения:

* обычный текст — `text-sm` / `text-base`;
* заголовки — умеренно крупные;
* основной заголовок страницы обычно `text-2xl` или близкий размер;
* не использовать огромные заголовки без необходимости;
* основной текст — normal/regular;
* названия и важные элементы — medium/semibold;
* не злоупотреблять жирным шрифтом.

Иерархия должна создаваться преимущественно размером, весом, отступами и цветом, а не декоративными элементами.

## Layout

Предпочтительно использовать:

* `max-w-*` для ограничения ширины контента;
* большие горизонтальные и вертикальные отступы;
* аккуратное выравнивание;
* понятную визуальную группировку элементов.

Для форм и небольших самостоятельных страниц допустима центральная колонка ограниченной ширины.

Не растягивать небольшие формы на всю ширину экрана.

Не создавать чрезмерно плотные интерфейсы.

## Карточки

Карточки должны быть сдержанными.

Предпочтение:

* белый фон;
* тонкая серая граница;
* умеренное скругление (`rounded-xl`, `rounded-2xl`);
* очень мягкая тень или отсутствие тени.

Не использовать:

* сильные тени;
* градиенты;
* декоративные рамки;
* яркие фоны;
* glassmorphism без явной необходимости.

Карточка должна визуально отделять содержимое, но не привлекать к себе внимание.

## Формы

Все формы сайта должны выглядеть единообразно.

Input:

* белый фон;
* тонкая серая граница;
* умеренное скругление;
* комфортная высота;
* небольшой горизонтальный padding;
* спокойный placeholder;
* аккуратный focus state.

Label:

* небольшой размер;
* medium;
* тёмно-серый цвет;
* находится над input;
* небольшой отступ между label и input.

Ошибки:

* красный цвет;
* небольшая подпись непосредственно под соответствующим полем;
* поле с ошибкой получает красную границу/focus;
* не использовать огромные alert-блоки, если ошибка относится только к одному полю.

Общая ошибка формы может отображаться отдельным компактным сообщением над формой.

## Кнопки

Основная кнопка:

* тёмный фон;
* белый текст;
* умеренное скругление;
* medium font weight;
* комфортная высота;
* hover должен быть небольшим изменением оттенка;
* focus должен быть заметным, но аккуратным.

Не использовать ярко-синие кнопки как основной стиль сайта, если нет специальной причины.

Вторичные действия:

* outline;
* ghost;
* текстовая ссылка.

Иерархия действий должна быть очевидной: на странице обычно одна primary action.

## Ссылки

Ссылки должны быть визуально заметны, но не кричащими.

Предпочтение:

* тёмный/нейтральный цвет;
* medium weight;
* hover через underline или небольшое изменение оттенка.

Ярко-синий цвет для всех ссылок не использовать автоматически.

## Состояния

Все интерактивные элементы должны иметь состояния:

* normal;
* hover;
* focus;
* disabled;
* loading;
* error;
* success — когда применимо.

Loading-состояния должны быть простыми.

Например:

`Сохранить` → `Сохранение...`

Не использовать декоративные анимации без необходимости.

## Отступы

Использовать последовательную систему spacing.

Предпочтительно:

* `space-y-4`;
* `space-y-5`;
* `space-y-6`;
* `gap-4`;
* `gap-6`;
* `p-6`;
* `p-8`.

Не подбирать случайные значения отступов для каждого элемента.

## Скругления

Основные значения:

* небольшие элементы → `rounded-lg`;
* inputs/buttons → `rounded-lg` или `rounded-xl`;
* карточки → `rounded-xl` или `rounded-2xl`.

Не использовать чрезмерно круглые элементы (`rounded-full`) кроме:

* avatar;
* badge;
* небольших status indicators;
* явно круглых controls.

## Иконки

Иконки использовать умеренно.

Иконка должна помогать понять действие или состояние, а не быть декоративным украшением.

Не добавлять иконки ко всем кнопкам и заголовкам без необходимости.

## Адаптивность

Интерфейс должен нормально работать:

* на desktop;
* на tablet;
* на мобильном.

Мобильная версия не должна быть отдельным дизайном — это тот же интерфейс, адаптированный под меньшую ширину.

## Что запрещено без явной необходимости

Не использовать:

* градиенты;
* яркие разноцветные блоки;
* огромные hero-секции;
* декоративные иллюстрации;
* чрезмерные тени;
* glassmorphism;
* неоновые цвета;
* большое количество цветов;
* чрезмерные анимации;
* визуальный шум;
* "startup landing page" эстетику;
* декоративные элементы, которые не помогают пользователю выполнить задачу.

## Главный принцип

Интерфейс Family Education должен ощущаться как спокойный рабочий инструмент.

Пользователь должен в первую очередь видеть:

1. что это за страница;
2. какую информацию он должен прочитать;
3. что он может сделать;
4. результат своего действия.

Дизайн не должен конкурировать с содержанием.

При создании нового компонента сначала переиспользуй существующие визуальные решения проекта. Не создавай новый стиль для каждой страницы.

Если одинаковый элемент уже существует в проекте, его внешний вид должен быть переиспользован, а не реализован заново с немного другими цветами, отступами или скруглениями.

В дальнейшем предпочтительно вынести повторяющиеся UI-паттерны в переиспользуемые React-компоненты, например:

* `Button`;
* `Input`;
* `FormField`;
* `Card`;
* `Alert`;
* `PageContainer`.

Цель — постепенно превратить визуальные правила в настоящую общую UI-систему, а не просто копировать Tailwind-классы между страницами.
