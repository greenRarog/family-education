## Правила работы

1. Выполнять один согласованный ID за шаг; переходить дальше только в разрешённой пользователем последовательности.
2. В начале читать SESSION_CONTEXT.md, backend/AGENTS.md, строку задачи и связанные файлы; для UI также docs/design.md.
3. До изменений кратко записать цель и исходное состояние в журнал. В конце — результат, проверки и следующий ID.
4. Сохранять незакоммиченные изменения трёх репозиториев; не применять reset/clean или переписывание истории ради чистого дерева. Commit/push — только по отдельному поручению.
5. Не расширять задачу несвязанным рефакторингом. Отдельный дефект выделять в подпункт; при блокере записывать условие продолжения, не повторять заведомо неудачные попытки.
6. Проверять изменённое поведение. Различать PASS/FAIL/BLOCKED, код и реальный запуск; исключение из приёмки допускается по явному решению пользователя и не считается PASS.
7. Рабочие БД/VPS не использовать без отдельного поручения. Новые продуктовые ограничения согласовывать до реализации.
8. Журнал вести короткими итогами, без дублирования отчётов и истории диагностики; команды запуска хранить в README.
