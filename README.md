# Family Education

Платформа для семейного образования.

Проект помогает семьям и педагогам находить друг друга для организации небольших учебных групп, индивидуального или
группового обучения.

На текущем этапе проект ориентирован на РФ.

Пользовательские потоки проверены в локальной среде. Эта задача завершена: репозитории и CI-проверки разделены, frontend собирается отдельно от backend.

Workflow-файлы: [backend CI](.github/workflows/ci.yml) выполняет проверки Laravel и содержит legacy deploy job; [frontend CI](../frontend/.github/workflows/ci.yml) выполняет `npm ci`, audit, lint и build. У infrastructure repository GitHub Actions workflow нет; stage сейчас запускается вручную командой `./infrastructure/bin/stage`. Legacy deploy job всё ещё вызывает старый `backend/scripts/deploy.sh` и не управляет новой multi-repository инфраструктурой. Безопасный перенос stage deployment вынесен в будущие задачи.

# Development

Backend, frontend и инфраструктура находятся в отдельных репозиториях. Актуальная схема каталогов, клонирования и запуска описана в [руководстве по инфраструктуре](../infrastructure/README.md).

```text
family-education/
├── backend/
├── frontend/
└── infrastructure/
```

Для локальной разработки нужны Git и Docker Compose plugin. Основные команды:

```bash
./infrastructure/bin/local
./infrastructure/bin/artisan key:generate
./infrastructure/bin/artisan migrate
```

Приложение открывается на <http://localhost:8081>. Запуск на stage выполняется через `./infrastructure/bin/stage` после настройки production env-файлов.

Backend tests, style и static analysis запускаются командами Composer из `composer.json`. Полные команды запуска среды и работы с Docker находятся в infrastructure README.

## Architecture principles

Проект развивается как модульный Laravel application.

Бизнес-логика должна быть отделена от инфраструктуры и HTTP-слоя.

Основные доменные области:

```
Identity
Family
Teacher
Geography
Catalog
Advertisement
Response
Messaging
Notification
Moderation
```

На текущем этапе это модульный монолит, а не набор микросервисов.

Границы доменных областей должны сохраняться таким образом, чтобы при необходимости отдельный домен можно было в будущем
вынести в самостоятельный сервис.

## MVP scope

В MVP сознательно отсутствуют:

- мобильные приложения;
- платежи;
- подписки;
- сложные чаты;
- групповые чаты;
- расписания;
- документооборот;
- образовательные программы;
- автоматический matching;
- интеграции с внешними образовательными системами;
- подтверждение личности;
- рейтинги;
- отзывы;
- сложная система модерации.

Основная концепция MVP:
> Доска объявлений для семейного образования с возможностью связаться через отклик и личные сообщения.

### MVP hardening and operations

- Добавить лимиты на создание откликов и другие публичные действия; расширить антиспам-защиту.

- Проверить восстановление из backup; настроить мониторинг приложения, Docker и диска, а также error tracking.
- Определить SEO и analytics требования.
- Проверить/настроить расписание SSL renewal на VPS.
- Перенести legacy backend deploy job на новую инфраструктуру только после проверки текущих stage containers/volumes и плана сохранения данных; сейчас stage запускается вручную.

### Longer-term ideas
