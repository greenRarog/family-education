# Family Education — backend

Laravel API платформы семейного образования: семьи и педагоги публикуют
объявления, отвечают на них и общаются в личных диалогах. Frontend — отдельная
React SPA. Языки интерфейса и уведомлений: RU/EN/ES.

**Локальная версия готова к настройке и приёмке на VPS.**
Состояние документации: 6 ноября 2026. [План завершения разработки](docs/refactoring-plan-2026-10-26.md),
[перенос на другую машину](docs/machine-migration-2026-10-28.md),
[инфраструктура и запуск](../infrastructure/README.md),
[требования к VPS и замеры](../infrastructure/README.md#vps-resources).

## Что реализовано

| Область | Текущее поведение |
| --- | --- |
| Аккаунты | Регистрация семьи/педагога, вход/выход, восстановление и смена пароля, подтверждение email; session cookies и CSRF; Turnstile при регистрации и входе |
| Удаление аккаунта | [Самостоятельное удаление и политика хранения](#управление-аккаунтом) |
| Семьи | Приватный профиль, дети (будущая дата рождения запрещена), город/район/метро, настройки уведомлений |
| Педагоги | Профиль с предметами, географией, текстовыми сведениями об образовании и о себе; запрос публичности и одобрение/отклонение администратором |
| Объявления | `family_to_family`, `family_to_teacher`, `teacher_to_service`; черновик, редактирование, публикация, закрытие, фильтры и пагинация |
| Переписка | Один отклик на объявление от пользователя, один диалог на отклик, принятие/завершение, порционная история, unread/read receipts |
| Справочники и администрирование | Страны, города, районы, метро, предметы, запрещённые слова; рассмотрение публичности профиля педагога |
| Уведомления | События нового отклика/сообщения/истечения объявления; email, подтверждённые Telegram/MAX и отдельные настройки каналов |

Педагогический модуль уже есть в коде и покрыт
[TeacherWorkflowTest](tests/Feature/TeacherWorkflowTest.php). Модерация и жалобы реализованы; [правила и API](#модерация).

Публичные feed/show объявлений используют
[PublicAdvertisementResource](app/Http/Resources/Api/PublicAdvertisementResource.php):
персональные данные детей не включаются. Редактирование владельца получает
приватные поля отдельным запросом. Профиль семьи приватный; публичный профиль
педагога доступен постороннему после запроса владельца и одобрения администратором.

После принятия отклика переписываться могут оба участника. Завершение отклика
(`accepted → rejected`) запрещает новые сообщения обоим, сохраняя историю.
Само объявление при этом остаётся опубликованным. Ежечасная команда
`advertisements:close-expired` закрывает истёкшие объявления через scheduler.

Email и подтверждённые Telegram/MAX реализованы; внешняя доставка пока
не принята. По умолчанию `MAIL_MAILER=log`, `TELEGRAM_ENABLED=false`, `MAX_ENABLED=false`.
[Telegram: конфигурация, API и команды](docs/telegram-operations-f03-f05.md).
[MAX: сценарий, конфигурация и webhook](docs/max-linking.md).

## Репозитории и запуск

```text
family-education/
├── backend/
├── frontend/
└── infrastructure/
```

Это три Git-репозитория; корень workspace не является репозиторием. Рабочая
ветка — `main`. Правила env, volumes и обычной local-среды находятся в
[infrastructure README](../infrastructure/README.md). Local доступен через
`http://localhost:8081`; backend/auth должны обслуживаться с того же origin,
что и frontend.

Проверенный отдельный стенд A21 для настоящего API не требует реальных `.env`.
Из корня workspace:

```bash
./infrastructure/bin/e2e build
./infrastructure/bin/e2e start
./infrastructure/bin/e2e check
```

Адрес — `http://127.0.0.1:18081`. `check` требует Python 3; остальное использует
Docker. Команды `start` и `reset` восстанавливают тестовые фикстуры, `stop`
уничтожает временную БД. [Аккаунты и границы стенда](../infrastructure/environments/e2e/README.md).
Не использовать его для хранения рабочих данных.

Для обычной local-среды после создания env и установки зависимостей команды
Artisan выполняются через `./infrastructure/bin/artisan`. `key:generate`
нужен только новой установке без APP_KEY; восстановленным данным требуется
прежний ключ. [DatabaseSeeder](database/seeders/DatabaseSeeder.php) заполняет
только справочники и запрещённые слова, повтор не создаёт пользователей.

```bash
./infrastructure/bin/artisan db:seed
./infrastructure/bin/artisan admin:create admin@example.test --name="Administrator" --locale=ru
# Только local/testing: демонстрационные семьи, дети и объявления.
./infrastructure/bin/artisan db:seed --class=DemoSeeder
```

Для admin укажите свой email. Пароль вводится скрыто дважды, от 8 символов;
в аргументах/env не передаётся. Повтор не сбрасывает доступ существующего admin
и не повышает чужую роль. У нового admin email сразу помечен подтверждённым
доверенной консольной командой, без отправки письма. Существующие аккаунты
при повторном запуске не изменяются. DemoSeeder вне local/testing отказывает; известного пароля admin нет.
E2E использует отдельные одноразовые фикстуры.

DemoSeeder создаёт 24 тестовых объявления: по 8 на RU/EN/ES, с локализованной
пометкой «ТЕСТОВОЕ ОБЪЯВЛЕНИЕ!» / «DEMO ADVERTISEMENT!» / «¡ANUNCIO DE PRUEBA!».
На каждом языке представлены все три типа объявлений, разные города, возрасты,
предметы и форматы занятий. Демообъявления пока используют российские города;
добавление иностранных справочников не перемещает существующие объявления.
Чтобы посмотреть нужный набор, выберите язык в фильтре объявлений: переключение
языка интерфейса само по себе не фильтрует ленту. Повтор той же команды добавляет
EN/ES к прежним русским примерам, обновляет публикацию и связи без дубликатов.
Обычный `db:seed` по-прежнему заполняет только справочники.

## Страны и города

География хранится как `countries → cities → districts / metro_stations`.
У страны есть уникальный двухбуквенный код в верхнем регистре и название;
у города обязательный `country_id`, а название уникально внутри страны.
Семьи, педагоги и объявления сохраняют только `city_id`: страна всегда берётся
из города и не дублируется в этих таблицах. Район и метро по-прежнему проверяются
на принадлежность выбранному городу. Страну с городами нельзя удалить.

Миграция `2026_11_06_120000_add_countries_to_cities` создаёт RU и относит к ней
все города прежнего российского справочника, сохраняя ID и связи. Откат
отказывается удалять сведения о странах, если уже появились нероссийские города.
CountrySeeder запускается перед CitySeeder. Справочник содержит РФ и пять новых
стран: ES (50 городов), DE (50), PL (50), GE (20), RS (30), всего 200 новых городов.
Сидеры российских районов, метро и демоданных ограничивают поиск кодом RU,
поэтому одноимённый иностранный город не получит российские данные.

Новые данные лежат в [international_cities.json](database/data/international_cities.json).
Это локальный стартовый набор основных городов, а не полный справочник или
актуальный рейтинг по населению. Источник: [GeoNames](https://www.geonames.org/),
выборка `cities5000.zip`, лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
В JSON сохранены ссылка, дата получения, SHA-256 архива, ID GeoNames и описание
отбора/исправлений. Из набора исключены известные районы крупных городов;
для ряда названий восстановлено местное написание (München, Warszawa и др.).
Названия Грузии даны латиницей, Сербии — сербской латиницей.
Сидеры не обращаются к сети и повторно не создают города/страны и не меняют их ID.
Районы и метро новых стран пока не заполняются; их поля необязательны.

| API | Контракт |
| --- | --- |
| `GET /api/countries` | Публичный список `{id, code, name}` |
| `GET /api/cities?country_id=…` | Публичные города, необязательный фильтр страны; каждый содержит `country_id` и `country` |
| `GET /api/locations` | Как прежде требует сессии; дополнительно возвращает `countries`, города содержат страну |
| `GET /api/advertisements/feed?country_id=…&city_id=…` | Страна фильтрует объявления через город; несовместимые страна и город дают 422 |
| `/api/admin/countries` | CRUD справочника стран только для admin |
| `/api/admin/cities` | При создании/изменении обязательны `name` и `country_id`; уникальность пары проверяется API и БД |

Публичные карточки объявлений/педагогов и снимки новых жалоб содержат страну
в объекте города. Прежние снимки жалоб не переписываются. Связь страны
загружается пакетно вместе с городами: число запросов ленты не растёт с числом
объявлений. Регионы/штаты и отдельные переводы названий городов пока не
импортируются. Одноимённые города внутри одной страны пока не различаются.

Frontend и backend выпускать вместе с новой миграцией: старый admin-клиент
без `country_id` не сможет создавать города. Полный inventory выпуска теперь
содержит 30 миграций. Тестовые миграции/сидеры запускаются только на одноразовой БД.

## Проверка запрещённых слов

Общее правило `NoBannedWords` использует текущий словарь из БД на сервере.
Проверка нечувствительна к регистру, учитывает границы слов Unicode и приводит
канонически эквивалентные написания к NFC (например, испанскую букву с ударением).
Совпадения внутри других слов не блокируются. Точные фразы из админки также
проверяются. Подмена букв похожими символами/цифрами и разделение букв пробелами
не входят в этот словарный механизм; смысл текста он не анализирует.

BannedWordSeeder объединяет прежний `banned_words.json` и два новых локальных
списка: `banned_words_en.json` (40 записей) и `banned_words_es.json` (75).
Новые списки составлены для проекта: ненормативная лексика и грубые оскорбления,
без нейтральных медицинских/учебных терминов. Старый русский список сохранён;
его возможные ложные срабатывания можно исправлять отдельно через админку.
Повторный запуск дополняет словарь и не удаляет пользовательские записи.

Проверяются создание и изменение пользовательских текстов:

- Регистрация: имя, фамилия, имена детей, описание и образование педагога.
- Профили семьи/педагога и действие изменения имени аккаунта Fortify
  (последнее сейчас не опубликовано отдельным маршрутом).
- Описания объявлений, отклики, личные сообщения, комментарии жалоб.
- Названия справочников в админке и пояснения модерации/решений/апелляций.
- Перед публикацией старого черновика и одобрением профиля педагога текст
  проверяется повторно по актуальному словарю.

Отказ возвращает 422 с ошибкой конкретного поля до сохранения/уведомлений.
Frontend показывает объяснение на RU/EN/ES и сохраняет черновик сообщения.
Email, пароли, коды, технические идентификаторы и сам редактор бан-слов в эту
проверку не входят. Исторические записи не переписываются. Автоматические
снимки жалоб сохраняют исходное нарушение: жалобу можно подать с нейтральным
комментарием или без комментария, если выбранная причина это допускает.

Обновление справочников и словаря на подготовленной среде: обычный `db:seed`
из раздела выше. Только словарь: `db:seed --class=BannedWordSeeder`.

## Проверки backend

Команды ниже выполняются из `backend/` в среде разработки с PHP 8.4,
Composer 2 и расширениями для выбранной БД (`pdo_sqlite`/`pdo_pgsql`).
Docker/CI проекта используют PHP 8.4; необходимые инструменты определены
[composer.json](composer.json) и lock-файлом.

```bash
composer install --no-interaction --prefer-dist
composer lint
composer analyse
composer test
```

`composer lint` — Pint без изменения файлов; `composer analyse` — Larastan;
`composer test` очищает config cache и запускает тесты с SQLite `:memory:`.
`composer check` последовательно выполняет все три проверки. `composer lint:fix`
изменяет форматирование. Для запуска отдельных тестов, например:

```bash
php artisan test --filter=TeacherWorkflowTest
```

Полный набор в свежей тестовой БД:

```bash
php -d memory_limit=512M vendor/bin/phpunit
php -d memory_limit=512M vendor/bin/phpunit -c phpunit.pgsql.xml
```

PostgreSQL — отдельная `family_education_test`; настройки в
[CI](.github/workflows/ci.yml). SQLite пропускает PostgreSQL-проверки гонок/TRUNCATE.

## Управление аккаунтом

Настройки уведомлений через `/api/notification-settings` доступны семье
и педагогу, также при блокировке/неподтверждённом email. Интерфейс теперь есть
в обоих профилях. [NotificationSettingTest](tests/Feature/NotificationSettingTest.php)
проверяет чтение/запись и изоляцию аккаунтов, включая попытку передать чужой user_id.
Поля ответа: `email_enabled`, `telegram_enabled`, `max_enabled`. В PUT первые два
обязательны; отсутствие `max_enabled` сохраняет прежнее значение для старых клиентов.
Включить Telegram/MAX можно только после подтверждения соответствующей привязки.
Внешняя доставка — отдельная приёмка на VPS.

[Права, лимиты, последствия и сроки хранения](docs/account-lifecycle.md) — единый
источник правил. Удаление выключено до эксплуатационной приёмки на VPS.

| Метод и маршрут | Тело / результат |
| --- | --- |
| DELETE `/api/account` | `current_password`, `request_token`; 200 `deleted` либо 202 `pending`, `access_revoked`, `deleted_at` |
| POST `/api/account/deletion-status` | `request_token`; тот же результат без входа, но с CSRF |
| PUT `/api/account/password` | `current_password`, `password`, `password_confirmation`; 200 `password_changed`, `other_sessions_revoked=true` |

Изменения требуют своей session/CSRF. Необязательный `X-Expected-Account-Id`
сверяет аккаунт, не выбирает цель; несовпадение — 409 `account_changed`. UI
всегда передаёт его. Поля чужой цели запрещены. Неверный пароль — 422,
лимит — 429, недоступность удаления — 503. Доступность формы берётся из
`/api/user.account_deletion_available`; отсутствие поля также закрывает форму.

`request_token` — 32 случайных байта в 64 строчных hex-символах; в БД только
SHA-256. 200/`deleted` требует подтверждения независимого реестра; 202/`pending`
означает уже зафиксированное удаление и ожидание подтверждения. 404 проверки,
сбой сети или 5xx не доказывают откат. Результат имеет `Cache-Control: no-store,
private`; для проверки после выхода может потребоваться новая `/api/csrf` cookie.
[Поведение интерфейса](../frontend/README.md#управление-аккаунтом).

Версия сессий не даёт старому/поздно записанному входу восстановить доступ после
смены пароля; уже авторизованные запросы задним числом не отменяются. Миграции
жизненного цикла и версии сессий после удаления/очистки/смены пароля нельзя
откатывать обычным down без отдельного плана сохранности данных и отзыва входов.

## Служебные команды

[Расписание](routes/console.php): перечисленные команды выполняются каждый час
с `withoutOverlapping()`. Работоспособность scheduler на VPS ещё не подтверждена.

| Команда | Назначение |
| --- | --- |
| `php artisan advertisements:close-expired` | Единое [закрытие по сроку публикации](docs/action-rules.md#срок-публикации) |
| `php artisan accounts:purge-expired` | Очистка просроченной истории, завершённых дел и служебных записей без зависимостей |
| `php artisan accounts:confirm-deletions` | Повтор подтверждения реестра; ненулевой exit при оставшихся pending |
| `php artisan telegram:prune` | Очистка истёкших попыток привязки и старых технических update ID; [правила хранения](docs/account-lifecycle.md#telegram-привязки) |
| `php artisan max:prune` | Аналогичная очистка попыток и dedup MAX |

Независимый реестр и закрытое восстановление: [настройки и команды](docs/account-recovery.md).
`accounts:registry-init` и `accounts:reconcile-restored` не запускаются по расписанию.

Команды тестировать в отдельной БД. [Browser-проверка жизненного цикла и
подготовка стенда](../frontend/e2e-lifecycle/README.md); общий набор backend —
в разделе проверок выше. Тестовый `LifecycleFixtureProvider` не зарегистрирован
в обычном приложении и не является реализацией независимого реестра.

Блокировки и скрытия независимы; сохраняются сессии, история и прежние статусы.
Решение жалобы, санкции и журнал атомарны. Пересмотр добавляет новую запись;
старые решения неизменяемы. Приватные профили/дети/чужие сообщения не открываются.

### API

Session/CSRF по общим правилам. Admin GET разрешён без verification,
изменения требуют verified admin; гость — 401, другая роль — 403.

| Маршрут | Назначение |
| --- | --- |
| POST `/api/reports` | Подача жалобы активной verified семьёй/педагогом |
| GET `/api/admin/users`, `/{id}`, `/{id}/history` | Список, карточка и история; фильтр `state=all\|active\|blocked` |
| POST `/api/admin/users/{id}/block`, `/unblock`, `/appeal-rejected` | Блокировка, отмена, результат ручного пересмотра |
| GET `/api/admin/advertisements`, `/{id}`, `/{id}/history` | Фильтры `state=all\|hidden\|visible`, `status=all\|draft\|published\|closed` |
| POST `/api/admin/advertisements/{id}/hide`, `/restore`, `/appeal-rejected` | Независимое скрытие/восстановление/пересмотр |
| GET `/api/admin/reports`, `/{id}`, `/{id}/history` | Фильтры `status=all\|open\|resolved\|dismissed`, `target_type=all\|advertisement\|user`; по умолчанию open/all |
| POST `/api/admin/reports/{id}/resolve` | Решение с санкциями или ссылками на действующие меры |
| GET `/api/admin/dashboard` | `blocked_users`, `hidden_advertisements`, `open_reports`; текущие целые числа без прикладного кеша |

Списки/история: `page`, 20 записей, новые ID первыми. История находится в карточках.
`visible` означает отсутствие явного скрытия, а не гарантию публичности.

Жалоба: `target_type=advertisement|user`,
`context_type=advertisement|teacher_profile|conversation`, `context_id`,
`reason`, необязательный `comment` до 2000 символов (other — от 10 после trim).
Цель/снимок определяет сервер. Лимит 3/60 + 10/86400; успех 201 `report.id/status=open`,
открытый дубль — 422 `report_already_open`, недоступная цель — 404,
неверные поля/своя цель — 422; 429 с `Retry-After/retry_after`.

Санкция: `reason_code` из правил и `reason` 10–1000 символов после trim.
Отмена: непустой `reason` до 1000, `reason_code=restriction_removed|review`.
Необязательный `decision_id` защищает от устаревшей карточки (409).
Ответ: объект, `changed`, `action_id`; повтор достигнутого состояния не меняет
причину/журнал. Unblock также возвращает `expired_advertisements_count`.
Appeal-rejected требует действующий `decision_id` и непустой `reason`;
повтор исполнителя/решения/пояснения не дублируется, устаревшее решение — 409.

Решение жалобы: `status=resolved|dismissed`, непустой `resolution_note`.
Для resolved: `actions` (`block_user` и/или `hide_advertisement`) с отдельными
`sanction_reason_code/sanction_reason`, либо `existing_action_ids` действующих мер.
Скрытие доступно только для жалобы на объявление; dismissed не принимает меры.
200 содержит актуальный `report`; закрытая жалоба/снятая связанная мера — 409.
Внутреннее пояснение не подставляется в публичную причину санкции.

### Хранение и дальнейшие изменения

`users.block_action_id` и `advertisements.hide_action_id` ссылаются на текущие
неизменяемые решения. `reports` сохраняет контекст/снимок после исчезновения
цели; частичный уникальный индекс защищает один открытый дубль.
`report_resolution_actions` связывает решение с мерами. FK RESTRICT защищают
исполнителей/заявителей/решения; служебная очистка выполняется по
[правилам хранения](docs/account-lifecycle.md).
`AdminActionLogger::record()` вызывается внутри той же транзакции, что переход;
ошибка откатывает всё. Записи сериализованы блокировками user → advertisement,
решение жалобы сначала блокирует report. Новые защищаемые бизнес-маршруты
должны явно применять актуальную модерацию. События/уведомления — после commit;
очередь повторно проверяет санкции, отменённое после восстановления не досылается.
Откаты миграций допустимы только с планом сохранения данных и учётом FK;
не использовать их как рабочую операцию отмены санкций.

Целевой сквозной тест: `php -d memory_limit=512M vendor/bin/phpunit --filter=ModerationLifecycleTest`;
для PostgreSQL добавить `-c phpunit.pgsql.xml`. Очередь:
`--filter='ModerationDelivery|HiddenAdvertisementDelivery'`.
